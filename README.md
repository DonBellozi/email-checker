# Проверка e-mail

Внутренний веб-сервис для быстрой проверки адресов электронной почты и расшифровки служебных сообщений о доставке.

## Что реализовано

- Публичная пользовательская страница без авторизации.
- Локальная админка `/admin`.
- Один универсальный ввод: один адрес, много адресов, Outlook-форматы, `mailto:`, `SMTP:`, фрагменты текста.
- Не более 100 найденных адресов за одну проверку.
- Дубли отображаются все, но техническая проверка одинакового адреса выполняется один раз.
- В таблице показываются:
  - исходный фрагмент;
  - статус-разделитель;
  - очищенный адрес;
  - короткий результат.
- Синтаксическая проблема подсвечивается точечно.
- Если домен синтаксически корректен, но технически не подтвержден, выделяется доменная часть целиком.
- Кириллица:
  - `vasya@мир.рф` — допустимо;
  - `вася@мир.рф` — допустимо;
  - `вася@gmail.com` — `Проверьте имя`;
  - смешение кириллицы и латиницы внутри имени или домена — ошибка соответствующей части.
- IDN `.рф` преобразуется в Punycode только для технических DNS-запросов.
- Проверка домена:
  - MX;
  - fallback на implicit MX при отсутствии явной MX-записи;
  - A и AAAA MX-хостов;
  - подключение к TCP/25 и чтение SMTP banner;
  - отправляется только `QUIT`, `MAIL FROM` / `RCPT TO` не используются.
- IPv6 используется при наличии маршрута у Docker-контейнера; при недоступности автоматически остается IPv4.
- Кеш доменов:
  - успешная проверка по умолчанию 7 суток;
  - отрицательная 24 часа;
  - временная ошибка 30 минут;
  - все значения меняются в админке.
- Подсказка исправления строится только по редактируемому списку стандартных почтовых доменов.
- История пользовательских проверок не хранится.
- Расшифровка статусов доставки:
  - отдельный SMTP-код, например `550 5.1.1`;
  - полный текст Mailer-Daemon / DSN;
  - `Action: delivered / delayed / failed / relayed / expanded`;
  - enhanced status code;
  - несколько `Final-Recipient` в одном DSN;
  - дополнительные признаки SPF, DKIM, DMARC, blacklist, relay denied, quota, message size, greylisting.
- Справочник enhanced status codes редактируется в админке.

## Запуск

```bash
cp .env.example .env
```

Обязательно измените в `.env` пароль администратора и `SESSION_SECRET` перед первым запуском:

```dotenv
ADMIN_USERNAME=admin
ADMIN_PASSWORD=сложный-пароль
SESSION_SECRET=длинная-случайная-строка
```

Затем:

```bash
docker compose up -d --build
```

Пользовательский интерфейс:

```text
http://IP-СЕРВЕРА:8083/
```

Админка:

```text
http://IP-СЕРВЕРА:8083/admin
```

Проверка работоспособности:

```text
http://IP-СЕРВЕРА:8083/health
```

## IPv6

Сетевой модуль проверки работает в dual-stack режиме и пытается использовать AAAA-адреса MX, если настройка IPv6 включена в админке.

Чтобы исходящие подключения контейнера действительно ходили по IPv6, Docker-хост и Docker network должны иметь рабочую IPv6-маршрутизацию. Если IPv6 в Docker не настроен, проверка автоматически продолжится по IPv4.

Для входящего доступа публикация `8083:8000` работает через механизмы Docker-хоста; доступ по IPv6 также зависит от конфигурации Docker/фаервола хоста.

## TCP/25

Для подтверждения существования почтового сервера сервис подключается к MX по TCP/25 и читает приветствие `220`. Адрес конкретного получателя на внешнем сервере не проверяется.

Если DNS/MX корректен, но TCP/25 недоступен, результат будет `Не удалось проверить`, а не `Проверьте домен`: причиной может быть блокировка исходящего SMTP на самом Docker-хосте или у провайдера.

## Данные

SQLite хранится в:

```text
./data/email-checker.db
```

В базе находятся только:

- настройки;
- кеш доменов;
- список стандартных доменов;
- справочник SMTP/DSN-кодов;
- локальная учетная запись администратора с PBKDF2-хешем пароля.

Введенные пользователями адреса и тексты Mailer-Daemon в историю не записываются.

## Основные API

```text
POST /api/check
Content-Type: application/json

{"text":"Иванов <ivanov@mail.ru>; user@example.com"}
```

```text
POST /api/delivery
Content-Type: application/json

{"text":"550 5.1.1 User unknown"}
```
